# Pricing Strategy

The best revenue model for this type of product is a mix of recurring subscriptions and usage-based fees.

## Core pricing model

### 1. Free tier

For developers and early experiments:

- 1,000 message credits / month
- basic analytics dashboard
- 1 connected wallet / project
- community support

### 2. Pro tier

For startups and product teams:

- $29–$99/month
- higher message quotas
- analytics and event monitoring
- API access
- priority support

### 3. Enterprise tier

For teams building real production infrastructure:

- custom pricing
- SLA and uptime commitments
- private deployment support
- advanced monitoring and custom routing rules

## Usage-based add-ons

Charge on top of subscriptions for heavy use:

- message fee per cross-chain action
- priority routing fee
- enterprise verification fee
- custom integration / support fee

## Example pricing

```text
Free:       $0/month       1k messages
Pro:        $49/month      100k messages + analytics
Scale:      $199/month     1M messages + API + priority support
Enterprise: Custom         SLA + private deployment + custom support
```

## Revenue optimization

To maximize revenue:

- make tiers clear and simple
- bundle analytics and monitoring into paid plans
- charge enterprise customers for custom integrations
- add premium routing features for high-volume users

## Why this works

The platform creates real operational value for teams doing cross-chain work. That means pricing is justified by:

- reduced operational complexity
- better observability
- lower failure rate
- faster team execution

## Recommended monetization flow

1. Free users test the platform
2. Teams upgrade to Pro for observability + API access
3. Large organizations pay for enterprise routing and custom contracts
4. Protocol revenue supports staking, treasury, and token incentives
